# Mux AI chapters — PRISM integration

PRISM now supports three levels of chapter data, in priority order:

1. **Authored chapters:** a supplied chapter WebVTT track or explicit marker list.
2. **Mux AI chapters:** an existing Mux `chapters` track generated by Mux Robots and attached to a public Mux asset; PRISM's server-side bridge reads it.
3. **Automatic navigation fallback:** meaningful subtitle-timed dialogue points when readable cues are available, otherwise accurately spaced timeline markers. **These are not AI or detected scene cuts.**

## Playing any Mux VOD in PRISM

Open the PRISM showcase with `?liveMux=YOUR_PUBLIC_MUX_PLAYBACK_ID` and select **LIVE ACTION**. The player uses Video.js v10's Mux element, Mux storyboard previews, captions if provided by the asset, and automatically available chapter navigation.

This also works when the asset has not had chapter metadata generated yet: the user can navigate using transcript or time markers. Existing cinematics with authored chapters take precedence.

## Enable true AI chapter generation once, for all new uploads

This is an **account-level Mux operation**, not an action initiated on every viewer visit.

1. In your Mux account, prepare auto-generated captions on uploaded videos (Mux Robots `generate-chapters` requires ready captions and audio). For videos without dialogue/captions, use the Mux Robots **analyze-structure** workflow, which can use visual evidence, rather than assuming transcripts exist.
2. Configure a Mux **Robots Directive** for newly ingested video assets. Have it wait for subtitle readiness, run `generate-chapters` (or `analyze-structure`), and set `update_asset_chapters: true` so the AI-generated chapters become a real Mux text track. Check billing and the output replacement behavior before enabling the directive account-wide.
3. In Cloudflare Workers → `prism-videojs-v10` → Settings → Variables and secrets, add these **encrypted Worker secrets**:
   - `MUX_TOKEN_ID` — Mux API token ID with video read access
   - `MUX_TOKEN_SECRET` — matching Mux API token secret
4. Redeploy if Cloudflare requires it. Never place the secrets in GitHub files, browser code, or URLs.
5. Confirm `/api/mux/chapters?playback_id=YOUR_PUBLIC_MUX_PLAYBACK_ID` returns `{"chapters":[...]}` after the AI job completes, then reload the player's LIVE ACTION view.

The `worker/index.js` bridge uses the **read-only** Mux API to look up the playback ID, validate that it belongs to a public VOD asset, retrieve its ready `chapters` track, then fetch the public chapter JSON. Visitors cannot trigger paid Mux Robots jobs through PRISM. When secrets or chapters are absent, it returns an empty array and the frontend uses its existing navigation fallback.

The Mux Robots directive / billing settings **are not activated automatically by installing this code**. An authorized Mux account owner must enable the ingestion workflow and add the Worker secrets.

### Safety and service limits

- Only public Mux playback IDs are supported by this showcase bridge. Signed/DRM assets require a separate trusted authentication flow.
- The Mux API token never leaves the Worker. No browser has permission to generate AI chapters or edit an asset.
- Mux Robots is a paid service; generation depends on account entitlements, asset readiness, and successful jobs.
- Transcription-derived sections and evenly spaced fallback markers are clearly distinguished from authored chapter data. They are not mislabeled as AI-detected cuts.
